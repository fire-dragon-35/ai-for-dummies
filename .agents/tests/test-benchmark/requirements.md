# Benchmark
Changes to the agent setup cost or save tokens and time and change the quality of the code agents write, so the same prompt runs in repositories with and without the setup and the results are compared

Benchmark: `.agents/skills/benchmark/run.sh`, run as `sh run.sh [--task <task>] [--runs <n>] [--prompt <text>] [--claude <command>]`. Task: the directory `tasks/<task>` next to the benchmark, or else the directory `<task>`; without `--task`, `tasks/todo`. Prompt: the `--prompt` value, or else the content of `prompt.md` of the task. Agent command: the `--claude` value, or `claude`. Run: one repository in a new directory that the agent command works in. Setup side: runs whose repository has the setup of this repository installed with `--hooks`. Plain side: runs whose repository has no setup. Run name: `with-<i>` for the i-th run of the setup side and `without-<i>` for the i-th run of the plain side, counting from 1. Side name: `with` for the setup side and `without` for the plain side. Lines written: the lines of the files of a run that are not tracked or ignored by git, without files in `.agents/hooks/`, `.agents/metrics/`, `.agents/skills/`, `.agents/repository-context/`, `.claude/`, `node_modules/`, `reviewed` files and `package-lock.json`. Setup files: `.git/`, `.agents/`, `.claude/`, `AGENTS.md`, `CLAUDE.md` and `node_modules/`. Code files: the files written by a run that end in `.js`, `.mjs` or `.cjs`, without test files, which are files in a directory named `test`, `tests` or `__tests__` or whose name contains `.test.` or `.spec.`

- R1: When run, the benchmark shall create `<n>` runs on the setup side and `<n>` on the plain side, each a git repository with one commit, and run the agent command once in each with `-p` and the prompt
- R2: When run without options, the benchmark shall make 3 runs per side with the prompt of the task `todo` and the agent command `claude`
- R3: When the runs finish, the benchmark shall print one line per run that starts with its run name and holds its cost, wall time, output tokens, cache read tokens, cache write tokens, subagents and lines written, taken from the agent's session files of that run as the reporter of the metrics component counts them
- R4: When the runs finish, the benchmark shall print one line per side that starts with its side name and holds the average, lowest and highest value of each figure of R3
- R5: The benchmark shall print the absolute path of a directory that holds the repository of each run in a subdirectory named after its run name
- R6: If an option is unknown or `--runs` is not a positive whole number, then the benchmark shall print its usage on standard error and exit with status 2 without running the agent command
- R7: When run with `--task`, the benchmark shall give every run the prompt of that task
- R8: If the task does not exist or has no `prompt.md` and no `--prompt` is given, then the benchmark shall name the problem on standard error and exit with status 2 without running the agent command
- R9: When the task has `acceptance.mjs`, the benchmark shall run `node acceptance.mjs <repository>` for every run after all runs finish and show the share of passed checks of the JSON object `{"passed", "total"}` on the last line of its output as a percentage on the run line and the side line, counting a script that prints no such object as 0%
- R10: When the task has `review.md`, the benchmark shall copy the files of every run without the setup files to a directory whose name does not contain the run name, run the agent command there with `-p` and the content of `review.md`, and show the average `score` of the JSON object in its answer on the run line and the side line
- R11: When the task has `eslint.config.mjs`, the benchmark shall show for every run the number of ESLint problems that this configuration finds in the code files per 1000 lines of code files, and the percentage of duplicated lines in the code files, on the run line and the side line
- R12: The acceptance script of the task `webapp` shall print a JSON object with `passed`, `total` and the names of the `failed` checks, pass every check for a correct app and fail checks of the input validation for an app that accepts invalid input
- R13: When the task has `acceptance.mjs`, the benchmark shall write the names in the `failed` list of the acceptance script of every run, under its run name, to `acceptance.md` in the directory of R5
- R14: When the task has `review.md`, the benchmark shall write the scores and notes of the review of every run to `review.md` in the directory of R5
